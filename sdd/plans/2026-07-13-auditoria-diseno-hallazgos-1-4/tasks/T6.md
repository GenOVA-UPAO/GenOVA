## 3a — Panel derecho vacío por defecto

Archivo: `frontend/src/features/ova-workspace/components/modals/phase-select-modal.component.ts`
(+ su `.html`).

- `hovered: Resource | null = null` (campo plano) → `readonly hovered = signal<Resource | null>(null)`.
- `previewResource` (getter) → `readonly previewResource = computed<Resource | null>(...)` con la
  cadena de fallback pedida: `hovered() > último pick de la fase activa > currentList[0]` (antes
  caía a `null`). `currentList` (getter existente, ya reactivo vía `recursos()` signal) se reutiliza
  tal cual, sin duplicar lógica.
- **Decisión no pedida explícitamente pero necesaria para que el `computed()` sea correcto**:
  `step` y `picks` también se convirtieron de campos planos a `signal`. Motivo: `computed()` de
  Angular solo re-evalúa cuando cambia una signal leída durante su ejecución; si `previewResource`
  hubiera quedado leyendo `this.step`/`this.picks` como campos planos, el panel habría mostrado
  contenido **desactualizado** al cambiar de pestaña de fase o al seleccionar un recurso sin pasar
  por hover (el `computed` memoiza y no vuelve a correr aunque la plantilla se re-renderice por otro
  evento). Con el getter original esto no pasaba porque un getter se reevalúa en cada ciclo de CD,
  pero un `computed()` no. Se propagó el cambio a los usos de `step`/`picks` dentro del propio
  archivo (`currentPhase`, `limitReached`, `total`, `phasesSelected`, `isSelected`,
  `selectionIndex`, `toggleResource`, `confirm`) y al template (`step.set(i)`, `step() === i`,
  `picks()[p.key].length`, `previewResource()`). No se tocó ningún consumidor externo — se verificó
  que `PhaseSelectModalComponent` solo se usa vía `[initialSelections]`/`(onConfirm)` en
  `ova-creation-view.component.ts`, sin acceso directo a `.picks`/`.step`.
- El estado vacío (`@if (!resource())`) se mantiene solo en mobile vía el `className` por defecto de
  `gn-resource-preview-panel` (`hidden sm:flex ...`), sin cambios.

## 3b — Mini-wireframe por `wire` + campo `returns`

Nuevo archivo: `frontend/src/features/ova-workspace/components/modals/resource-wireframe.component.ts`
(179 líneas). Standalone, OnPush, selector `gn-resource-wireframe`, `input.required<WireframeKind>()
wire` + `input<string>() phaseColor` (default `#3B82F6`, mismo default que el resto del modal). Un
único `@switch` con los 12 casos (exhaustivo, sin `@default` "muerto" — se agregó un `@default` de
todas formas como red de seguridad ante datos corruptos). El color de acento se aplica una sola vez
en el contenedor raíz (`[style.color]="phaseColor()"`) y todo el boceto usa `border-current` /
`bg-current/N` / `stroke-current/N`, evitando bindings de estilo repetidos por nodo.

Boceto elegido por `wire` (todo CSS/SVG inline, cero assets externos):

| wire | boceto |
|---|---|
| `comic` | grilla 2×2 de 4 paneles redondeados |
| `video` | rectángulo con borde + triángulo ▶ centrado (vía `border-*` trick, sin SVG) |
| `audio` | botón ▶ circular + 8 barras de onda con alturas variables (`waveHeights`) |
| `chat` | 3 burbujas con `rounded-bl-sm`/`rounded-br-sm` alternando `self-start`/`self-end` |
| `lab` | matraz (cuello + cuerpo `rounded-b-full`) con 2 burbujas — deliberadamente distinto de `game` para que sean reconocibles por separado |
| `quiz` | 3 filas de círculo (radio) + barra de línea con ancho variable (`quizWidths`) |
| `read` | título ancho + 4 líneas de texto con anchos decrecientes (`readWidths`) |
| `map` | 4 pines (puntos) en posiciones absolutas `%` + `<svg><line>` conectándolos |
| `game` | tablero 3×3 (`grid-cols-3 grid-rows-3`) con una ficha llena (X) y dos anillos (O) |
| `timeline` | línea horizontal + 4 hitos circulares con `bg-background` para "cortar" la línea |
| `form` | 2 filas de mini-label + barra de input con ancho variable (`formWidths`) |
| `card` | card con barra de header + 3 líneas de cuerpo con anchos decrecientes |

Wireado en `resource-preview-panel.component.ts`:
- `<gn-resource-wireframe [wire]="info.wire" [phaseColor]="phaseColor()" />` dentro de un contenedor
  `aspect-video w-full overflow-hidden rounded-lg border border-border bg-muted/30`, colocado
  **arriba** del bloque "Qué genera" (bullets), como pedía el plan.
- `info.returns` se renderiza como subtítulo (`text-xs text-muted-foreground`) justo debajo del
  wireframe y antes de "Qué genera". Se confirmó por grep (`getResourcePreview`/`ResourcePreviewInfo`)
  que `returns` no se pintaba en ningún otro sitio del código antes de este cambio.
- `ResourceWireframeComponent` se añadió al array `imports` del panel.
