## Alcance

Batch D de la migración de 72 archivos `logging` → `structlog` kv-style.
17 archivos del dominio OVA (routers CRUD, fases) + Users (settings, admin) + Roles.

Todos: `import logging` → `import structlog`, `logging.getLogger(__name__)` →
`structlog.get_logger(__name__)`. Ninguno usaba `logging.<constante>` (p.ej.
`logging.INFO`), así que no aplicó la excepción del punto 1 — `import logging`
se eliminó por completo en los 17 archivos.

`ova/crud/edit_router.py` y `ova/crud/edit_view_router.py`: el logger estaba
declarado pero sin ninguna llamada `.log/.warning/.exception` en el archivo —
solo swap de import/definición, sin conversión de mensajes.

`users/admin/account_router.py`: mismo caso (logger declarado, sin uso).

## Decisiones de naming kv (interpolación → kv-pairs)

- `ova/router.py`: `object_key`, `ova_id` (renombrado desde mensajes con
  `ova=%s` → campo `ova_id`).
- `ova/crud/edit_helpers.py`: `object_key` (upload fallback en revert).
- `ova/crud/export_router.py`, `ova/phases/history_router.py`: `ova_id`.
- `ova/phases/add_phase_router.py`: `phase_id`, `ova_id`, `version_id` — mensaje
  `"Added phase %s to OVA %s (version %s)"` → `"phase added"` + 3 kv-pairs.
- `users/settings/*_router.py` (llm_settings, ova_settings, api_keys,
  resource_configs, enabled_models): patrón uniforme `user_id=current_user.id`
  en los `commit_or_500`-style excepts (`"X write failed for user %s"` →
  `"X write failed", user_id=...`).
- `users/admin/platform_settings_router.py`: `providers=list(updates)` en el
  log de refresh de catálogo (evité el nombre genérico `updates` por claridad
  semántica). Mensajes sin datos dinámicos (`"Platform config write failed"`,
  `"LLM model config write failed"`) solo cambiaron de logger, mensaje intacto
  (en minúscula por consistencia de estilo, sin alterar semántica).
- `users/admin/nodes_config_router.py`: `"Nodes config write failed"` → solo
  swap de logger (sin datos dinámicos disponibles en el except).
- `users/admin/helpers.py` (`commit_or_500` compartido): `"Admin DB write
  failed during %s"` → `"admin DB write failed", op=op`. `op` no colisiona con
  ninguna palabra reservada de structlog.
- `roles/delete_router.py`: `"Reassignment failed during delete_role"` → solo
  swap de logger (sin datos dinámicos en el except; el contexto del error ya
  vive en el mensaje estático).

Ningún log de este batch usó nombres de campo reservados (`event`, `level`,
`logger`, `timestamp`, `exc_info`, `stack_info`) — no fue necesario renombrar
por colisión.
