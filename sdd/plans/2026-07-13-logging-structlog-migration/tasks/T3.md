# T3 — Batch C: migración logging → structlog en dominio Generation

## Archivos migrados (11)

- `backend/generation/jobs/jobs_router.py` — solo swap de import/logger (no tenía llamadas `logger.*`).
- `backend/generation/jobs/jobs_router_helpers.py`
- `backend/generation/jobs/jobs_runner.py`
- `backend/generation/jobs/jobs_runner_exec.py`
- `backend/generation/jobs/jobs_progress.py`
- `backend/generation/jobs/jobs_materialize.py`
- `backend/generation/regen/regen_service.py`
- `backend/generation/regen/regen_agents.py`
- `backend/generation/regen/regen_pipelines.py`
- `backend/generation/regen/regen_persist.py`
- `backend/generation/errors/error_log_service.py`

Ninguno de los 11 usaba `logging.` para otra cosa que `getLogger` (verificado con
`grep -n "logging\."` por archivo antes de tocar), así que en todos se reemplazó
`import logging` → `import structlog` sin excepción de import dual.

## Decisiones de naming kv

- Mensajes estáticos pasados a minúsculas/frase corta (estilo `http_middleware.py`),
  ej. `"Prometheus graph failed for job %s"` → `"Prometheus graph failed"` con
  `job_id=job_id`.
- Campos comunes normalizados entre archivos: `job_id`, `resource_id`, `phase_id`,
  `ova_id`, `error_id`, `phase_type`, `resource_type`, `attempt`, `max_attempts`,
  `concept`, `fallback`, `title`.
- `resource.error attempt %d/%d failed: %s` (jobs_runner_exec.py) → kv-pairs
  `phase_type`, `resource_type` (renombrado desde `rtype` posicional), `attempt`,
  `max_attempts`, `error=type(exc).__name__`.
- `regen_service.py::_finalize_edit` catch-all: `logger.error("Edit regen failed for
  OVA %s: %s", ova_id, exc)` → `logger.error("edit regen failed", ova_id=ova_id,
  error=str(exc))`.
- Ningún campo colisionó con las claves reservadas de structlog (`event`, `level`,
  `logger`, `timestamp`, `exc_info`, `stack_info`); no hizo falta renombrar ninguno.
- `error_log_service.py`: `"Failed to persist generation error log (error_id=%s)"`
  → `"failed to persist generation error log"` + `error_id=error_id` (el error_id ya
  se genera antes del try, no es un secreto — solo un UUID opaco).
