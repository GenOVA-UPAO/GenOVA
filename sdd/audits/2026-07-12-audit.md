## Hallazgos — Medio

### [C12] Migración gradual a structlog en el resto del backend
- **Archivo**: `backend/**/*.py` (loggers stdlib existentes)
- **Escenario de falla**: módulos que siguen con `logging.getLogger` emiten bien vía ProcessorFormatter, pero no aprovechan campos estructurados ni contextvars salvo lo que mergea el foreign_pre_chain.
- **Remedio propuesto**: adoptar `structlog.get_logger` en nodos Prometheus / jobs al tocar esos archivos; no hace falta big-bang.

### [C1] verify -Quick no ejercita imagen Docker prod
- **Archivo**: `frontend/Dockerfile.prod`, `docker-compose.prod.yml`
- **Escenario de falla**: path `dist/frontend-ng/browser` incorrecto solo se detecta al `docker compose -f docker-compose.prod.yml build`.
- **Remedio propuesto**: un smoke CI opcional `docker build -f frontend/Dockerfile.prod frontend` o documentar en smoke tests.

## Hallazgos — Bajo

- `LANGSMITH_API_KEY` se copia a `os.environ` (patrón oficial LangSmith); asegurar que ningún logger imprima `environ` completo (R8 ya cubre mensajes).
- Tipografía Helm aplicada en login/navbar/dashboard; auth register y otras páginas chrome aún con clases ad‑hoc.
- `pnpm install --no-frozen-lockfile` en Docker frontend: más tolerante en dev, menos reproducible que `--frozen-lockfile`.

## Quick wins

1. Smoke build de `Dockerfile.prod` en CI o local una vez.
2. Activar LangSmith en `.env` local con `LANGSMITH_TRACING=1` + API key de prueba y generar un OVA fake/real para validar traces.
3. Extender `hlmH1`/`hlmMuted` a register/forgot-password.

## Deuda estructural de fondo

- Adopción completa de structlog en Prometheus/LLM (plan aparte si se quiere trazabilidad uniforme en logs de generación).
- Unificar Dockerfile backend dev/prod context (compose.prod usa root + `backend/Dockerfile.prod`; compose dev usa `./backend`) — ya era así, no introducido aquí.
